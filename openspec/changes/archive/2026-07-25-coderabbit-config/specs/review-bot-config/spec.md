# Review bot configuration

## ADDED Requirements

### Requirement: Docstring coverage does not apply here

`.coderabbit.yaml` SHALL set `reviews.pre_merge_checks.docstrings.mode` to
`"off"`. Every key path it adds MUST match the published CodeRabbit schema,
because `scripts/check-yaml.ts` validates only that a file parses and a
mistyped key configures nothing silently.

#### Scenario: The check is off, not loosened

- **WHEN** `.coderabbit.yaml` is read
- **THEN** `reviews.pre_merge_checks.docstrings.mode` is `"off"`
- **AND** no `threshold` is set, since it has no meaning while the check is off

#### Scenario: The key paths are real

- **WHEN** each key path added by this change is compared against
  `https://storage.googleapis.com/coderabbit_public_assets/schema.v2.json`
- **THEN** every one exists in the schema with the value it is given

### Requirement: Generated and settled paths are out of review scope

`reviews.path_filters` SHALL exclude `openspec/changes/archive/**`,
`src/fixtures/snapshot.json` and `**/*.woff2`. It MUST NOT exclude
`openspec/**` as a whole, because the same patterns drive the bot's git
sparse-checkout and the branch's own delta spec is review context.

#### Scenario: An archived change

- **WHEN** a branch touches `openspec/changes/archive/**`
- **THEN** the bot reports nothing on those files

#### Scenario: The branch's own delta spec

- **WHEN** a branch adds `openspec/changes/<name>/specs/**/spec.md`
- **THEN** the bot still reads and reviews it

#### Scenario: The generated fixture

- **WHEN** `src/fixtures/snapshot.json` is regenerated by
  `generate_fixture.py`
- **THEN** the bot reports nothing on it

### Requirement: The bot does not re-run this repo's own linters

`reviews.tools` SHALL disable `biome`, `yamllint` and `actionlint`, each of
which already runs in `lint.yml` or the pre-commit hook. Tools this repo does
not run itself, including `markdownlint` and the secret scanners, SHALL stay
enabled.

#### Scenario: A formatting violation Biome already blocks

- **WHEN** a branch contains a violation `bunx biome check` reports
- **THEN** the bot does not report it a second time

#### Scenario: A Markdown problem no gate here checks

- **WHEN** a branch contains a Markdown issue
- **THEN** the bot still reports it

### Requirement: Learnings are scoped by decision, not by visibility

`knowledge_base.learnings.scope` SHALL be set to `"local"` explicitly, rather
than inheriting the `auto` default, which resolves by repository visibility.

#### Scenario: The repository changes visibility

- **WHEN** the repository is made private
- **THEN** learnings stay scoped to this repository

### Requirement: Coding guidelines cover the indexed docs only

`knowledge_base.code_guidelines.filePatterns` SHALL match `**/CLAUDE.md` and
the flat `docs/*.md`, and SHALL NOT be widened to `docs/**/*.md`. Session
save-points under `docs/context/` are committed but never loaded
automatically, and `filePatterns` has no negation syntax with which to
exclude them.

#### Scenario: A context save-point exists

- **WHEN** `docs/context/<topic>-<yyyy-mm>.md` is committed
- **THEN** it is not read as a coding guideline

#### Scenario: An indexed doc is added

- **WHEN** a new `docs/<topic>.md` is added per the growth protocol
- **THEN** it is read as a coding guideline with no config change

### Requirement: A disabled check carries its reason in the config

Where this repository switches a review-bot check, tool or path off,
`.coderabbit.yaml` SHALL state why beside the key, so the decision is legible
to someone editing the config who has not read this spec.

#### Scenario: Reading the config alone

- **WHEN** a developer opens `.coderabbit.yaml` and finds `docstrings` off
- **THEN** an adjacent comment says the project has no docstring rule and that
  a permanently amber check devalues the checks beside it
- **AND** the comment rules out restoring a threshold as the fix

#### Scenario: A disabled tool

- **WHEN** a developer finds `biome` disabled under `reviews.tools`
- **THEN** an adjacent comment names the gate that already runs it
