# rtk and its alternatives — survey of 2026-10-01

Whether a command-output compressor earns a place in this project's agent
sessions, and what else could cut the same context for less risk. Written for
the `Harness` card *Decide whether rtk earns its place — survey first*; kept
because the question returns whenever sessions get longer or agents start
running unattended.

**This is a survey, not a decision record.** Every figure below was read on
2026-10-01: rtk at tag `v0.50.0`, Claude Code `2.1.285` and its documentation,
bun `1.4.2`. Re-check before depending on one — all three ship weekly.

## The verdict

Not now. The share rtk could compress safely is about a tenth of tool output,
and reaching it means excluding exactly the commands review rests on
(`git diff`, `gh`), while the hook it installs grants `allow` from its own
re-implementation of the permission rules. Revisit when agents run long
unattended sessions on the orchestrator host and `rtk discover`, run in a
sandbox outside this project's policy, shows a share worth that hook — and
settle the two open questions at the end of this file first.

## rtk, read from its source

- **Integration** — a `PreToolUse` hook on `Bash` that rewrites the command to
  an `rtk` equivalent. `Read`, `Grep` and `Glob` never pass through it.
- **`exclude_commands`** (`src/discover/registry.rs:1540`,
  `compile_exclude_patterns`) — a pattern without a leading `^` becomes
  `^<escaped pattern>($|\s)`, a prefix bounded by a word break; one with `^`
  is a regex. So `"git diff"` excludes `git diff …` and leaves `git status`
  alone. It misses `git --no-pager diff` and `git -C <path> diff`, which need
  a regex.
- **File reads** — `cat`, `head` and `tail` rewrite to `rtk read`, whose
  `--level` defaults to `none`, "full content" (`src/main.rs`). Lossless, and
  so saves nothing on the largest category above. `src/core/filter.rs`'s
  comment-stripping levels apply only when asked for.
- **Permissions** — the hook checks the command against deny, ask and allow
  rules it loads itself (`src/hooks/permissions.rs`) from four files: the
  project's `.claude/settings.json` and `settings.local.json`, and the user's
  two. Managed settings and `--settings` are not read. On a matching allow
  rule it returns `permissionDecision: "allow"` with the rewritten command
  (`src/hooks/hook_cmd.rs`, `process_claude_payload_from_decision`); on a
  deny it passes the command through untouched for Claude Code to refuse.
  That is a second implementation of this repository's permission policy,
  outside `checks/agent-permissions*`.
- **Recovery** — truncated output is kept on disk and recalled with
  `rtk recall <hash>`.
- **Supply chain** — `brew install rtk` resolves to `homebrew/core` `rtk`
  0.50.0, homepage `rtk-ai.app`, Apache-2.0: the rtk-ai project, not the
  unrelated "Rust Type Kit" nor one of the many forks republishing its README.
  `v0.50.0` was released 2026-09-24. Telemetry is off unless opted into;
  `RTK_TELEMETRY_DISABLED=1` pins that.

What is left to compress once `git diff`, `git show` and `gh` are excluded —
they are the input of every review gate and of `/coderabbit` — is roughly
tests, other `git`, part of `grep` and part of the compound commands: an
estimate by category of about a tenth of tool output, not a measurement.
`rtk discover` would measure it but needs rtk installed.

## Alternatives

| Option | What it covers | Cost | Standing |
| :- | :- | :- | :- |
| Claude Code's own output limit | a valid `Bash` result over ~30,000 characters arrives as a file path plus a 2,000-character preview; a failing one as a ~10,000-character head-and-tail excerpt (tools reference, *Output limits*). `bashOutputMaxChars` resizes it | none — on by default | already in force; the extreme case rtk sells on is handled |
| bun's own test output | outside a terminal `bun test` prints only the summary: 99–104 characters for each of four passing test files measured, with or without `--only-failures` | none | already in force; nothing for rtk to save on tests here |
| a language server for TypeScript | navigation by symbol (definitions, references, call hierarchy) instead of `grep` then `sed`; type errors reported after each edit without a separate type-check | **not** the official `typescript-lsp` plugin: it starts `typescript-language-server`, which wraps `tsserver`, and the project's TypeScript 7.0.2 ships no `tsserver.js` — the wrapper would fall back to a global 5.x and diagnose with a different compiler (the `tsc` on `PATH` here is a global 5.8.3). TypeScript 7 carries its own server instead: `node_modules/.bin/tsc --lsp --stdio` answered `initialize` as `typescript-go` 7.0.2 with definition, references, implementation, workspace symbol, call hierarchy and pull diagnostics. No new dependency; a project-local plugin pointing at that binary | aimed at file reading, but measured narrowly: of the reading share, 52.7% is markdown, 37.2% touches `.ts`/`.tsx`, and a `grep` for a symbol-like token is 2.2% — its value is correctness and edit feedback more than context |
| a project-owned `PostToolUse` hook | `updatedToolOutput` replaces a tool's result (hooks reference) — shaping one measured noisy command, under this repository's own checks | code to own and test; lossy by design, so never on a gate's input | only once a specific command is measured as noisy |
| subagents for wide reads | a search across many files returns a conclusion, not the files | already the session policy | in force |
| `context-mode` (mksglu) | runs commands in a sandbox, indexes raw output in SQLite FTS5, returns ranked excerpts; MCP tools plus six hooks | redirects `Bash` **and `Read`** into its sandbox, and its `PreToolUse` hook blocks commands — a third policy layer; Elastic License 2.0 | rejected — the same objection as rtk's hook, over a wider surface |

## Open questions

- **How Claude Code combines decisions from several `PreToolUse` hooks on one
  call.** The hooks reference says they run in parallel and does not state the
  precedence. With rtk installed, its `allow` and `scripts/command-guard.ts`'s
  refusal would meet on the same call.
- **Whether a hook's `allow` passes the auto-mode classifier.** The hooks
  reference advises using the permission system rather than a hook "to enforce
  a hard allow or deny", which says hooks are not the enforcement layer, not
  what an `allow` from one skips.
